What I would do next

In priority order: each one fixes the biggest remaining risk for the least money and effort.

  1. Daily EBS snapshots with Data Lifecycle Manager (kept 7 days). The whole system lives on one disk in one Availability Zone; snapshots turn a 30-minute manual rebuild into minutes, for cents a month. This is the gap named first in the Well-Architected review.
  2. Stop LibreChat retrying errors that cannot succeed, and add a fallback model. When the free quota runs out, LibreChat retries for about two minutes and the customer waits for nothing. Failing fast with a clear message, and falling back to a second model or provider, would turn the most common real failure into a short delay.
  3. Grow the test set to 30 harder questions, including tricky ones. Ten easy questions all pass, which says little. Thirty, with half-answered and misleading questions, would give an honest accuracy number and show where the documents need work.
  4. Turn on GuardDuty and stop the server overnight. GuardDuty would flag a compromised instance or unusual API calls for a few cents a day; an EventBridge schedule stopping the instance from midnight to 07:00 would cut compute cost by nearly 30%.
  5. Move the database to a managed service (Amazon DocumentDB, or MongoDB Atlas in the same region) if real customers ever used it, so backups, patching and failover are handled by the provider instead of my scripts.
