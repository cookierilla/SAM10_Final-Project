Kapé Lumen: an AI café assistant, run properly

A virtual barista that answers customers' questions about a (fictional) café. I took an existing open-source chat app, made it into the café's own assistant, put it on Amazon Web Services (AWS), and then ran it the way a real service should be run: watched, backed up, locked down and largely automated.

What the system does

Customers of Kapé Lumen, a made-up café with branches in Baguio and Quezon City, open a web page and ask the assistant, "Lumen", everyday questions: How much is an iced Spanish latte? Are you open on Christmas Day? Can I bring my dog? Lumen answers only from the café's own documents (menu, branches and hours, loyalty card, house policies, FAQ). It does not take orders or payments, and it will not give allergy or medical advice: for that it sends you to the staff.

What was wrong with how it was run

Out of the box, the chat app I started from (LibreChat) is built for trying things out on one computer, not for serving customers. It talked over plain, unencrypted HTTP. Its database had no password. Its secret keys were the public example values that everyone who downloads it gets. The AI key sat in a text file. Nobody would know if it went down, there were no backups, and it ran seven programs, several of which this café does not need (see Baseline).

What I changed

  • Made it the café's own. New name, logo, colours and wording, the café's own documents stored in Amazon S3, and one fixed assistant instead of a menu of AI models.
  • Locked it down. Encrypted HTTPS only, a password-protected database that the internet cannot reach, every key kept in AWS Parameter Store instead of in files, no remote-login port open, two-factor sign-in on every AWS account, and an audit trail of every change.
  • Made problems visible. A dashboard and ten alarms that email me when the site is down, answers fail or slow down, the server is unhealthy, or a backup is missing. Every question is logged with how long it took and whether it worked.
  • Made the data recoverable. A backup every night to S3, kept 14 days, and a restore that is tested automatically every Sunday.
  • Automated the routine. A nightly quality check that asks ten test questions and emails the score, and automatic deployment: a change pushed to the code repository is tested and goes live without me logging in to the server.
