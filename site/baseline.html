Baseline: the environment before I touched it

The starting point is LibreChat v0.8.9-rc1 exactly as its own docker-compose.yml runs it, which I brought up on my laptop on 2026-11-06 (screenshots E-05). It is a good developer setup and a poor production one: it is built so anyone can try it in five minutes, which means every safety setting is off by default.

What I found

AreaBefore (stock LibreChat, 2026-11-06)Why it matters
TransportPlain HTTP on port 3080Passwords and chats cross the network readable by anyone on the path.
DatabaseMongoDB started with --noauthAnything that can reach the database can read or delete every account and conversation.
App secretsPublic default CREDS_KEY, JWT_SECRET from .env.exampleEveryone who downloads LibreChat has the same keys, so sign-in tokens could be forged.
AI keyStored in .env on diskOne careless commit or copied folder leaks a key that can run up a bill.
Admin accessWhoever has the machineNo separate accounts, no MFA, no record of who changed what.
LogsFiles inside containers, no retention, no alertsLogs vanish when a container is replaced, and nobody is told when something fails.
MonitoringNoneAn outage is noticed only when a customer complains.
BackupsNoneA lost disk means every account and conversation is gone for good.
Containers running7, including RAG API, vector database, search and an admin panelUnused services cost memory and money and are more things to patch and secure.
Answer quality for the caféNot answerable: the stock app has no café dataIt would invent prices and hours, or say it does not know.
Cost$0 (my laptop), and not reachable by customersThe "after" cost is the price of actually serving customers; see Results.

Each of these rows has a matching fix in the security before-and-after table or on the monitoring and backup sections of the same page.
